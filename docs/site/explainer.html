Write Amplification in a Simplified Page-Mapped NAND Flash Translation Layer

Author: Arnav Pandya • Software: FlashWAF v1.0.0 • DOI: 10.5281/zenodo.23655212

1. The Fundamental Asymmetry of NAND Flash Memory

NAND flash memory exhibits a core physical constraint: erase-before-write. In raw NAND flash:

  • Read operations occur at page granularity (e.g., 4 KiB).
  • Program (write) operations also occur at page granularity, but only on physical pages that have been previously erased.
  • Erase operations occur only across entire erase blocks (e.g., 32 or 64 contiguous pages).

Because operating systems frequently rewrite individual logical sectors, a direct in-place update would require erasing an entire block for every single-page write. Flash controllers resolve this by interposing a Flash Translation Layer (FTL).

2. Page-Mapped FTL and Out-of-Place Updates

In a page-mapped FTL, logical addresses (LBAs) are dynamically mapped to arbitrary physical pages. Pages transition through a three-state lifecycle:

  • FREE: Empty and erased. Ready to be programmed.
  • VALID: Holds current user data referenced by the L2P mapping table.
  • INVALID: Holds obsolete data from a prior write to an LBA that has since been rewritten elsewhere.

When the host issues a write to an active LBA, the FTL allocates an erased FREE page in the open write block, programs the updated payload, updates the L2P table, and flags the previous physical location as INVALID.

3. Greedy Garbage Collection and Relocation Cost

As host writes deplete available free pages below a threshold (gc_threshold_free_pages), the FTL triggers Garbage Collection (GC):

  1. Victim Selection: The controller scans candidate blocks and greedily selects the block with the highest count of invalid pages (breaking ties with lower historical erase counts).
  2. Valid-Page Relocation: If the victim block contains remaining valid pages, those pages must be copied to free pages in another block, incrementing the GC copy counter.
  3. Block Erasure: The victim block is erased, resetting its pages to FREE.

The Write Amplification Factor (WAF) is defined as:

WAF = (Host Page Writes + GC Relocation Page Writes) / Host Page Writes

4. The Impact of Mapped Occupancy and Over-Provisioning

Let $N$ be total physical pages and $M$ be active mapped LBAs. The mapped occupancy ratio is ρ = $M / N$. As ρ increases, the available over-provisioning space ($1 - \rho$) shrinks, reducing the number of invalid pages in candidate blocks and forcing GC to relocate more live valid pages per reclaimed block.

5. Skewed Locality Without Hot/Cold Data Separation

When write access is skewed (e.g. 80% of writes target 10% of LBAs) but all data writes to a single shared allocation frontier:

  • Hot pages are updated rapidly and become invalid in older blocks.
  • Cold pages remain valid for extended durations.
  • Because hot and cold data share blocks, victim blocks with heavy invalid data almost always contain lingering cold pages that must be migrated forward.

In FlashWAF's 30-seed paired experiment, hot/cold traffic yielded higher write amplification than uniform traffic across all occupancies (+0.33 at 40%, +0.61 at 70%, and +0.80 at 85%), demonstrating the penalty of non-partitioned allocation.

6. Research Boundaries

Notice: FlashWAF is a controlled algorithmic model. It omits hardware timing, multi-channel bus interleaving, dynamic wear leveling pools, crash recovery journals, and ECC. It serves as an accessible educational and comparative tool, not an empirical hardware emulator.
